## 递归派子 subagent 建议

- **T6（LazyColumn 主体重构）**：体量最大（预计 300+ 行改动），建议 L1 agent 内部再拆为两个 L2 任务：
  - L2-a：分组渲染框架（header sticky + group items）
  - L2-b：父会话卡片 subagent 子行展开/收起动画
- **T5（项目 Header UI）**：`⋮` 菜单逻辑略复杂，但体量可控，不需要再拆。
- **T1/T2/T3/T4/T7**：均不需要递归拆分，单 agent 可独立完成。
- **递归深度上限**：L0（主调度）→ L1（T1–T7）→ L2（T6 内部子任务），不超过 3 层。

## 风险点 / 阻塞

1. **T2 UiState 结构变更是全局阻塞点**：T4/T5/T6/T7 均依赖 `SessionListUiState` 的新数据形状（分组列表 + subagent 索引）。T2 若延迟或数据结构反复变更，Wave 3 全部阻塞。建议 T2 先定义好 sealed class / data class 接口，Wave 3 可提前 stub 开发。

2. **`SessionListScreen.kt` 1449 行单文件并发冲突**：T3/T4/T5/T6 都需要改同一文件。Wave 3 并行时须约定各 agent 的改动区域（T3 顶部 Banner、T4 搜索栏、T5 Header composable、T6 LazyColumn body），合并时可能产生 git 冲突，需要一次集成 merge 步骤。

3. **DataStore + Hilt 注入作用域**：T1 如果 DataStore singleton 作用域定义不当，T2 注入时可能出现 `@Singleton` vs `@ActivityRetainedScoped` 冲突，需要在 T1 阶段确认注入 scope。
