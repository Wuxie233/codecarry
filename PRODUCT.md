# Product

## Register

product

## Users

OC Remote serves experienced developers who monitor and steer remote AI coding work from an Android phone. They move between long-running conversations, inspect tool activity, respond to approvals, and reconnect to work throughout the day.

## Product Purpose

OC Remote makes remote OpenCode, Codex, and Pi Roundtable work readable and controllable on mobile. Success means a user can resume recent work immediately, understand live agent state, scan a long technical conversation, and take the next action without fighting connection management or dense controls.

## Brand Personality

Warm, precise, and composed. The interface should feel humane during long reading sessions while retaining the clarity and efficiency of a professional developer tool.

## Anti-references

- A Claude visual clone or imitation of another product's branding.
- A terminal-themed interface that treats density and darkness as personality.
- A generic Material demo made from large tinted cards, oversized pills, and default component spacing.
- A dashboard that exposes every status and control at the same visual priority.
- Decorative gradients, glass surfaces, neon accents, or motion without state meaning.

## Design Principles

1. **Return to the work.** Recent and active conversations are the primary home experience; server management supports that work.
2. **Let content lead.** Assistant prose reads as a continuous document. Containers are reserved for user prompts and bounded work units such as tools, reasoning, diffs, approvals, and errors.
3. **Reveal complexity when it becomes relevant.** Common actions stay visible; expert controls remain nearby through predictable menus, sheets, and expandable units.
4. **Make live state legible.** Streaming, connection, retry, approval, and completion states appear where the user is already looking and never rely on color alone.
5. **Preserve professional momentum.** Navigation, touch feedback, keyboard behavior, drafts, scroll position, and recovery paths should reduce repeated work.

## Accessibility & Inclusion

Target WCAG 2.2 AA and Android accessibility guidance. Core flows require 48dp touch targets, meaningful TalkBack semantics and state announcements, non-color status cues, readable contrast in light/dark/AMOLED themes, usable layouts with large system text, reduced-motion behavior, and adaptive phone/tablet/landscape layouts.
