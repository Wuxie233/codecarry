# Domain docs

Use a single-context layout: root CONTEXT.md and docs/adr/.

Before domain exploration, read CONTEXT.md and any ADRs relevant
to the work. If either is absent, proceed without scaffolding it.

Use the glossary's vocabulary in specifications, proposals and tests.
Surface conflicts with existing ADRs explicitly.

Create or extend domain documents through domain-modeling when
durable terminology or architectural decisions are established.
